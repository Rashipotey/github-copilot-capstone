## Planning Decisions

The following concrete values and interfaces settle architecture details for planning. They are planning decisions, not additional user decisions, and do not expand the approved scope.

- **CLI:** `--repo PATH` defaults to `.` and resolves from the caller's current directory. Scope options are mutually exclusive: `--working-tree` is the default and may be stated explicitly; `--staged` selects index versus `HEAD`; `--base REV --head REV` must be supplied together and compares those endpoint trees directly, not a merge base. Working-tree scope is tracked unstaged changes only (`git diff`); staged scope is staged changes only (`git diff --cached`, index versus `HEAD`). Neither includes untracked files. There is no combined scope. Invalid, missing, or unpaired revisions fail before evidence reads or proposal analysis.
- **Other options:** repeatable `--exclude GLOB` accepts repo-relative POSIX globs (`*`, `?`, `[]`, and `**`); `--output-dir PATH` defaults to `<canonical-repo-root>/docsync-output/`, and a relative supplied path is relative to the repository root. There is no overwrite flag. If either artifact target exists, refuse before diff collection even for an empty diff. Canonically validate output paths, reject symlink/reparse-point/non-regular targets and collisions with source docs or repository inputs, then stage and atomically create absent targets with a same-filesystem hard link. If no-replace linking is unavailable, fail closed without replacing. Generate only `docsync-report.md` and `docsync.patch`; do not add an ownership manifest. `--max-changed-files N` defaults to `100`; `--max-diff-bytes N` defaults to `1048576` bytes of textual Git diff. Numeric limits must be positive. At the exact maximum, processing is permitted; any value above a maximum is reported and never silently truncated. Exclusion matches are case-sensitive against normalized repo-relative paths; a matched directory pattern excludes its descendants. There are no built-in generated-file globs.
- **Git and path safety:** use `git -C <canonical-root>` with argument arrays, never a shell. Resolve each explicit revision with `git rev-parse --verify --end-of-options REV^{tree}` and pass only the resulting tree IDs to the endpoint diff. Invalid revisions fail before content analysis. Parse Git paths as NUL-delimited data; reject absolute paths, `..`, malformed encodings, and paths escaping the canonical root. Never follow a repository symlink for evidence: reject symlink/reparse-point components and Git symlink blobs, recheck resolved containment immediately before reads, and report the skip safely. The supplied repository path itself may be a symlink; canonicalize it before establishing the repository root.
- **Finite resource ceilings:** each Git process has a **30-second timeout**; per invocation stdout is capped at **2 MiB** and stderr at **64 KiB**. A timeout or output-ceiling breach terminates/reaps the child and fails that stage; captured partial output is discarded, never analyzed as complete. A textual diff between 1 MiB and 2 MiB is recognized as over the configured diff limit and produces no proposals; a diff exceeding the 2 MiB capture ceiling fails closed with a sanitized resource-limit status. Each individual source or Markdown evidence file is capped at **256 KiB**; larger files are reported as skipped and cannot support a proposal. The cumulative raw-byte payload admitted for a run (selected diff plus unique source/config/Markdown evidence bytes) is capped at **32 MiB**; if the next complete evidence item would exceed it, stop proposal analysis and report the resource limit rather than use a partial evidence set. A file exactly at 256 KiB and a payload exactly at 32 MiB are permitted. The 32 MiB budget tracks input bytes, not Python object/string overhead, subprocess internals, or total process RSS; it is not a portable hard OS memory cap.
- **Binary/generated/unsupported inputs:** identify changed binary content from Git binary metadata (for example, `--numstat` binary markers) and NUL-byte checks on bounded content, never by filename extension. Skip binary content. Generated/irrelevant files are skipped only when matched by configured exclusions; unsupported types and unsafe/unreadable paths are skipped with a per-path reason. Every skipped input is included in the sanitized report/summary. An over-size Markdown file makes the Markdown candidate set incomplete, so no proposal may rely on target selection that could be affected by it.
- **Secret screening:** an initial, explicitly incomplete pattern set covers PEM private-key blocks; labeled credential assignments for password/passwd, secret, token, API/access key, client secret, and private key; HTTP Bearer/Basic authorization values; and JWT-shaped values. Redact captured values in safe evidence; exclude the entire evidence item for private-key blocks or uncertain match boundaries. Screen both raw diff sides and every source/config/Markdown item before downstream use; also screen repo-derived paths/diagnostics, proposal context, optional-request context, candidates, report, patch, and logs immediately before sinks. Re-screen immediately before any optional request and before artifact writes. If decoding/screening fails or a detected value remains in a candidate/final artifact, fail closed for the affected operation; emit only a fixed sanitized outcome where safe. If redaction removes needed support, withhold the proposal. Never claim complete secret detection.
- **Deterministic proposal allowlist:** only (1) a Python callable signature change matched by the same repo-relative module and qualified callable in old/new ASTs, with the complete old header occurring exactly once in an existing fenced Markdown code block; or (2) one changed JSON/TOML scalar key path with old/new values, where exactly one existing structured Markdown settings-table row has that exact path and old value. For settings rows, recognize a pipe-table row with a `Key`/`Path` column and a `Value`/`Current` column; recognize it with a narrow row parser without enabling a Markdown extension. Use escaped JSON Pointer paths for both source formats and canonical JSON scalar rendering for the exact old/new cell values; support strings, finite numbers, booleans, and JSON null, not TOML date/time values. Python signatures include all parameters, kinds, defaults, annotations, return annotation, and `async` marker; extract the complete header from source and require an exact unique anchor after line-ending and fence-indent normalization. Proposals replace only the signature header or scalar cell value. Preserve all surrounding Markdown. No general prose generation.
- **Validator and output contracts:** all three validators return a structured `pass`, `fail`, `warning`, or `inconclusive` result with sanitized actionable detail and evidence references where applicable. Missing/uncheckable evidence is never pass. Markdown parsing uses `markdown-it-py` CommonMark only, with no optional extensions; local links are resolved against repository paths and the proposed virtual Markdown state, with no remote fetches. The only output names are `docsync-report.md` and `docsync.patch`; no additional generated artifacts are created. Either existing target blocks the run before diff collection, including empty diffs, and the writer independently refuses both artifacts if either exists. Validate canonical output paths, reject symlink/reparse-point components and non-regular-file targets, and reject collisions with source docs or any repository input. Screen and stage both artifacts on the output filesystem, then atomically create each absent target with a no-replace hard link. Fail closed if unavailable; never fall back to replacement. This is not a portable two-file transaction. On a partial write, preserve any target that already exists, retain/report an artifact this run successfully created, report the failed artifact and path in the terminal summary (and in the report when report creation succeeds), and never claim the pair completed. Clean up only this run's temporary files. No code path applies the patch or edits source docs.
- **LLM and CI:** offline deterministic operation has no provider dependency and makes no external request. Do not add an enable flag or provider implementation until separately approved. The optional interface remains provider-neutral and disabled by default. GitHub Actions is intended; `pytest` is approved; `pip-audit` and Bandit are planned checks, but availability and configuration are unverified. A future workflow must surface unavailable/failing tools and may report success only for checks actually run successfully.
